# caller-preflight-map Specification

## Purpose
定义 wire 入口余额预检的调用者映射：映射随开户自动建立、读取满足准实时、未映射调用者按 fail-closed 策略处置（平台凭据除外），使套餐额度的 402 硬停对全部真实客户生效。

## Requirements

### Requirement: 映射随开户自动建立

客户开户时，其入口身份与 sub2api 账户的映射自动写入 registry 侧持久存储；写入方使用开户流程在建户时已持有的账户标识，不做二次查询。映射不复制客户任何凭据明文（只存账户标识）。

#### Scenario: 新客户自动受限
- **WHEN** 一个完成开户（含映射写入）的新客户在余额大于零时经 wire 入口调用
- **THEN** 调用放行且受预检约束

### Requirement: 余额耗尽硬停

余额门仅对可超额档（超额单价大于零）的客户生效：此类客户的 sub2api 账户余额耗尽后，其经 wire 入口的调用被 402 拒绝，与 wire 侧结算口径一致。无超额档位（超额单价为零，含免费档）不检查余额——其硬停由当月行数门承担，免费档零余额不因此被误杀。

#### Scenario: 余额归零即拒
- **WHEN** 可超额档（超额单价大于零）客户 C 的 sub2api 账户余额降至零，C 的长命 key 经 wire 入口发起调用
- **THEN** 入口返回 402 余额不足，调用不达上游

#### Scenario: 免费档零余额可调用
- **WHEN** 免费档客户（sub2api 余额为零、当月读取未达含额）经 wire 入口调用
- **THEN** 调用放行，仅受行数门约束

### Requirement: 未映射调用者 fail-closed（平台凭据除外）

在 deny 策略开启的生产环境，未映射的调用者被拒绝而非静默放行；持有平台管理语义（admin scope）的凭据不受客户余额门约束，保持放行——其计量归属为平台轨。

#### Scenario: 漏配开户即时暴露
- **WHEN** 一个开户流程漏写映射的客户凭据经 wire 入口调用，且 deny 策略开启
- **THEN** 调用被拒绝并留下可定位的拒绝原因，而不是静默放行成账单窟窿

#### Scenario: 平台凭据不受影响
- **WHEN** 平台服务凭据（admin 语义）在无任何映射的情况下经 wire 入口调用
- **THEN** 预检放行，行为与映射机制引入前一致

### Requirement: 映射读取准实时

预检对映射的读取允许短缓存，但开户写入后须在一个有界窗口（分钟级）内对入口生效，无需重启任何服务。

#### Scenario: 写入后有界生效
- **WHEN** 映射写入完成后经过不超过缓存窗口的时间，该客户发起调用
- **THEN** 预检按新映射判定

### Requirement: 当月行数门

预检在余额判定之外增加当月行数门：客户当月累计读取行数（rows_returned）达到其档位含额时，后续调用以月度额度耗尽语义拒绝、不达上游。额度数据由 wire 侧额度查询端点提供，预检读取允许分钟级有界缓存；额度服务不可达时 fail-closed（拒绝并留下可定位原因），不因放行产生无门用量。平台管理语义凭据（admin scope）不受行数门约束，计量归平台轨。

#### Scenario: 到量即拒不达上游
- **WHEN** 客户当月累计读取行数达到档位含额后经 wire 入口调用
- **THEN** 入口返回月度额度耗尽，上游不收到该调用

#### Scenario: 额度服务故障 fail-closed
- **WHEN** wire 额度查询端点不可达
- **THEN** 预检拒绝调用并留下可定位的拒绝原因，而非放行

#### Scenario: 平台凭据豁免
- **WHEN** 平台服务凭据（admin 语义）经 wire 入口调用
- **THEN** 行数门不适用，行为与余额门豁免口径一致
