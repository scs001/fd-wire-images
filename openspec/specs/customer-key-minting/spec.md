# customer-key-minting Specification

## Purpose
定义客户长命 key 的铸造与吊销语义：平台可代铸权限恰为客户应得的 key（不继承铸造者权限）、归属明确到客户身份、吊销（含代吊）即时生效——使开户与退租全流程无需客户参与浏览器会话、也不放大平台凭据权限。

## Requirements

### Requirement: 代铸指定归属与组

平台服务身份可以代客户铸造长命 key：key 的归属身份（owner）与组快照在铸造时显式指定，key 的权限恰为该客户应得（共享业务面 + 自己的 cell），绝不继承铸造者自身的权限。

#### Scenario: 代铸权限恰如其分
- **WHEN** 平台服务身份为客户 C 代铸 key（指定 C 的身份与应得组），随后以该 key 列目录并调用
- **THEN** 该 key 可见可调的范围等于 C 的应得范围，看不到平台管理面，也看不到别家 cell

#### Scenario: 快照即所铸组
- **WHEN** key 铸造完成
- **THEN** 其组快照为铸造时指定的组；后续授权范围的调整经 scope 解析实时生效，key 本身无需重铸

### Requirement: 吊销即时且可代吊

客户 key 的吊销下一次调用即生效；除 owner 自吊外，平台服务身份可代吊任意客户 key，以支撑退租自动化。

#### Scenario: 代吊即时生效
- **WHEN** 平台服务身份吊销客户 C 的某把 key，随后该 key 发起调用
- **THEN** 调用被拒绝；吊销不可逆，重复吊销幂等报错而非误报成功

### Requirement: 铸造通道不新增凭据暴露面

自动化铸造可以使用 registry 既有的本机铸造通道完成，前提是所用信任材料不离开其现有存放主机；对外（集群侧）的铸造走显式的代铸 API，凭据面不因本能力扩大。

#### Scenario: 集群侧代铸不引入新信任材料
- **WHEN** 集群侧服务执行代铸
- **THEN** 它持有所需的是一把可审计的平台凭据，而非 registry 的根信任材料
