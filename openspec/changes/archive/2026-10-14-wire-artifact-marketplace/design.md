# Design: wire-artifact-marketplace

## D1 为什么产物市场与数据集市场同构而不共表

数据集市场（wire-dataset-marketplace）建于 `DatasetsBase`（`wire_datasets`
库）；产物住 `AiBase`（ai 切片库）。两者**分库**，共用一个市场表要跨库
（无跨库事务）——同构三表（subscriptions/grants/access_requests）各自建，
代码层抽公共模式但不强行合表。可见性字段同理：`dataset_asset_meta`
与 `artifacts` 各持一份，值域与语义逐字一致（四档 + open/approval）。

## D2 「只读看」的安全模型（grilling Q1/Q3 重写——初稿假设错误已修正）

**初稿的错误假设**：「渲染时服务端按发布方取数、订阅者只见聚合、计量记发布方」。
**侦察修正**：看板渲染是**纯前端读 spec**（`DashboardRenderer` 读
`panel.snapshot.rows`），**快照数据值内嵌在 spec 里**（生产实例实证：
E2E 宏观看板的 panel rows = [[4.8],[3.9],…] 为真实数值）。即：看板 spec
本身就是数据载体，渲染零引擎调用。

**因此「只读看」的真实语义（Q1 裁决 a）**：

- 看板/报告的市场分享 ≡ **发布方的分析成果（含发布时刻的数据快照）可供
  他人查看**——与「把这份分析发给对方」等价；
- 订阅者渲染**零引擎调用、零计量消耗**（纯读 spec 快照）；
- **文案必须如实披露**（Q1 硬要求）：市场面与渲染页显著标注
  「公开看板包含发布时刻的数据快照；订阅底层数据集才能取实时行数据」；
- **时效披露（Q3 裁决 a）**：渲染页显著标注快照时间（refreshed_at 从
  版本层的刷新响应取；spec 值缺失时诚实显「未知」），
  **SHALL NOT 自动触发刷新**（那会未经发布方同意消耗其额度）。

「看板公开 ≠ 数据集开放」仍然成立：订阅者拿不到**实时行数据**（数据面
`dataset_query` 仍按数据集市场规则，未订阅发布方数据集 → 拒），
但**必须承认**：快照时刻的那批数据值随看板可见——这是 Q1 裁决显式接受的
语义，不是漏洞。

## D3 「可复制」语义的绑定重映射（第二个重决策）

复制 = 把 spec 快照（`artifact_versions.spec`）复制为 caller 账号的新
artifact（draft，version=1）。难点在**看板面板绑定了 dataset_id**：

- caller 对某面板的数据集**有访问权**（自有 / 已订阅发布方的数据集 /
  定向授权）→ 重映射到**同一 dataset_id**（数据集归属不变，访问权独立
  校验——所以复制后 caller 能取到数，前提是他本来就订阅了那个数据集）；
- caller **无访问权** → 该面板标 `unbound`（spec 里加
  `"binding_status": "unbound"`，编辑器重绑入口带提示）——**不落假数据、
  不自动赋权**（用户裁决「数据仍需单独授权」的落地面）。

返回体带逐面板绑定报告（`bound` / `unbound` 计数 + 清单），诚实呈现。

**copy 的前置闸**：`allow_copy=true`（发布方显式允许）+ 订阅关系在
（open 档订阅即得 / approval 档已批准）。发布方不许复制 → 403 明确说明。

**快照剥离（Q4 裁决 a，硬要求）**：复制 SHALL **剥掉全部
`panel.snapshot`**——复制者拿到的是**分析结构**（面板布局/图表配置/
查询绑定），看板初始为空图（如实呈现「无数据，需绑定与刷新」）。
理由：与「数据仍需单独授权」一致；带快照复制 = 变相数据外带渠道。

**溯源指针（Q7 裁决 a）**：复制 SHALL 留 `copied_from_artifact_id`
（审计/未来 fork 谱系），**不做**跨客户更新提示（通知基建缺位；v2+）。

**复制权 = 订阅权（Q6 裁决 a）**：订阅关系本身就是闸（open 订阅即得、
approval 有人工批准）；不再给复制加独立审批层。

## D4 与既有「签名链接」的关系（两条通道并存，不替代）

- **签名链接** = 点对点、临时（7/30/90 天）、免登录、版本钉死——适合
  「把这个给某个人看一次」；
- **市场公开** = 登录客户面可发现、长期、带订阅关系、可撤回——适合
  「希望被更多人使用」；
两者并存，同一产物可以既有链接又在市场（互不干扰：链接 TTL 独立、
市场订阅独立）。

## D5 版本锚点与撤回（同数据集市场纪律）

- `published_version` = 进入非 private 档位时刻的 `artifact.version`；
- 市场「只读看」渲染**渲染最新已发布版本**（与链接的版本钉死不同——市场是
  持续订阅，跟随发布方更新；`published_version` 用于**审计锚点**而非钉死）；
- 撤回（改回 private）→ 订阅者渲染立即 403（下一次请求即失效，同数据集
  市场「撤回即时失效」纪律）；approval 档新订阅需重新审批。

## D5b 绑定数据集的敏感度硬闸（Q5 裁决 a）

发布方把看板设 `market` 时，SHALL 校验其**全部绑定数据集**的敏感度：
任一绑定数据集为「敏感」档 → 拒绝 market（422；允许 link/directed）。
这是红线 3 修订版的延伸——防「数据没开放、但看板把数据快照带出去」的
绕过路径（血媒：Q1 已承认快照含数据值）。

**同时发现既有缺口**：数据集市场的敏感度**事后**改档无互锁——数据集已在
market 在架，owner 之后把敏感度改成「敏感」，不会自动下架（assets PATCH
与 market set_visibility 无互锁）。本 change 两处一起堵：绑定数据集敏感度
校验在**发布时 + 订阅者渲染时**双点执行（渲染时命中敏感 → 拒绝渲染），
堵塞「数据没开放、看板把快照带出去」的绕过路径；数据集侧的事后互锁由
**Q13 裁决顺带修**（见 D12——assets PATCH 改敏感自动撤回 private + 留痕）。

## D6 迁移（0036，AiBase）

`artifacts` 增 `visibility`/`access_mode`/`published_at`/`published_version`/
`allow_copy`；三新表挂 `AiBase`（ai 库）。布尔默认 **`sa.text("false")`**
（PG 坑）；字符串默认 `sa.text("'private'")`。链头断言翻新（finddata 与
fd-wire 两根的链头测试各自核对——ai 切片在 fd-wire 根）。

**注意链头双根**：fd-wire 自己的 openspec 根有新 spec；但 alembic 链是
一条（`api/alembic/versions/`），链头从 `0035_quality_rules` → `0036`。

## D8 文案纪律（Q1/Q3/Q8 的落地）

市场详情/渲染页/发布弹层三处 SHALL 使用如实文案（i18n 双语）：

- 市场详情：明示「公开看板/报告包含发布时刻的数据快照」；
- 渲染页：显著展示快照时间 + 「数据可能已过期；订阅底层数据集可获实时
  行数据」；看不到新增行（快照剥离后的副本）时如实显「无数据」；
- 发布弹层：Q5 的一次性确认文案（含敏感度闸说明）。

**SHALL NOT** 使用「仅结构不含数据」「数据不出边界」等与事实不符的措辞
（Q1 的硬纪律：宁可吓退发布方，不许误导订阅者）。

## D9 快照时间来源（Q9 裁决 a）

`refreshed_at` 现不在 spec 里（是刷新响应字段）。本 change 改刷新路径：
产出新版本时 **spec 增 `refreshed_at` 键**（历史版本各自带准确时间戳；
旧版本无该键 → 渲染页诚实显「未知」不猜）。渲染页据 spec 的
`refreshed_at` 展示快照时间。

## D10 敏感度闸判定成本（Q10 裁决 a）

渲染面每次请求实时查绑定数据集的 `dataset_asset_meta.sensitivity`
（N 次主键查表，N≤10 量级可忽略）；**不缓存**——「改档立即生效」正是该闸
的目的，缓存只引入陈旧窗口。

## D11 报告的市场面（Q11/Q12 裁决）

- 详情结构摘要：标题 + 描述 + **`data_scope`/`data_range` 元信息**
  （既有 materialization 契约字段，非正文）；
- 订阅后阅读面：**先查 spec 有无 markdown 正文字段——有则用既有 md 渲染，
  无则落只读 JSON 查看器**（DashboardRenderer legacy 先例）；报告渲染器
  仍留后续 change。

## D12 数据集侧敏感度互锁（Q13 裁决 a——顺带修既有缺口）

数据集已在 market 在架 → owner 改敏感度为「敏感」→ 现状**不自动下架**
（缺口）。本批顺带修：`assets` PATCH 的敏感度变更处加互锁——改成「敏感」
且该数据集处于非 private 档位 → **自动撤回 private + 留痕**
（asset_meta_events 追加）；两通道（数据集/看板）一起严。

## D13 ROADMAP 结项勾注（Q15 裁决）

三件必须项全部交付后，ROADMAP 方向 B 写一条结项：规则引擎 +
数据集市场 + 看板/报告市场（附三批 change 名与日期）。

## D7 测试策略

- 市场三表 + 可见性：默认 private 铁律（SQL 层过滤）、四档往返、撤回即失效、
  approval 档闸、allow_copy 闸（false → 403）、定向授权；
- **敏感度硬闸（Q5）**：绑定敏感数据集 → 发布 market 422；渲染时命中 → 拒；
- **快照剥离（Q4）**：复制后 spec 无任何 snapshot 键（递归断言）；
- **详情结构摘要（Q8）**：未订阅者拿不到 config/snapshot（只 {id,type,title}）；
- 复制语义：全绑定（caller 有数据集权）/ 部分 unbound / 全 unbound 三态；
  spec 独立性（复制后改自己的不影响发布方）；
- 渲染路：订阅者渲染 200（发布方数据口径）+ 未订阅 403 + 撤回后 403；
  渲染快照**不含行数据**（honeypot 断言）；
- 控制台：可见性选择器四档 + allow_copy 开关 + 市场页三页签 + 复制按钮
  可见性条件；i18n 双语；
- 迁移：SQLite 全量 + PG14:5433 upgrade/downgrade。
