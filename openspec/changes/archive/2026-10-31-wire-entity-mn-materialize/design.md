# wire-entity-mn-materialize — Design

## D1 展开语义：桥驱动对表（INNER），不是左表保留

n:1/1:1 物化是 LEFT JOIN（左表行全保留、未命中 NULL）——「属性补全」语义；
m:n 的语义对象是**关系对的集合**，展开主体是桥行：一条桥行 → 一行结果
（源侧行 + 目标侧行）。无桥的源行不入结果（它没有关系对）；「未命中全 NULL」
的伪行会造出「源行存在但与谁都不关联却成行」的假数据，违背「绝不取邻值/不伪造」
纪律，故明确 INNER。

- 孤儿桥（桥行引用的源/目标主键值失存）：丢弃并计数上报（响应与台账如实
  「展开 N 对、孤儿桥丢弃 M 行」），不静默。
- 结果 schema：源列原名 + 目标列（撞名 `right_` 前缀），中间集列不进结果
  （纯路径；需桥属性时用户另声明「源 ↔ 中间集」的 n:1 link 物化）。
- 子集主键＝（源主键列, 目标主键列）成对键；桥重复行→结果重复，计入孤儿/重复
  口径如实标注。

## D2 引擎侧：扩 `customer_dataset_link`，不建新工具

- 同一工具加可选 junction 参数（中间集 + 两列）：提供→三端桥展开；缺省→既有
  两端 LEFT JOIN **逐字节等价**（既有测试网即回归）。
- 不建 `customer_dataset_link_mn`：沿 pipelines/service.py「无第二条物化路径」
  先例——两工具会把 api 分支选择、血缘解析、`derive_refresh` 全部分叉成二。
- 实施腿在 DAAS 引擎仓，移植到 cell 镜像实际构建线 `internal-main` 再 rollout
  （Wave F 实证教训：`main` 线 ≠ 构建线）。

## D3 护栏：估算前置 + 引擎行数闸双保险

- api 侧物化前先数桥行数，估算值（＝桥行数上限）超行数闸→422 如实给估算、
  零写、子集不登记。闸值读既有 link 行数上限**单一真源**（配置，不硬编码——
  「天花板类断言必须读单一真源」教训）。
- 引擎侧展开实数仍走既有行数闸（整批拒绝，子集保持原状）。
- 估算 ≥ 实数（孤儿桥丢弃只会更少），两处文案区分「估算/实数」不混称。

## D4 档位闸三端

既有两端 cell 档闸扩为三端（源/目标/中间集），任一免费档 403
PLAN_TIER_REQUIRED 如实、文案与实际档位一致。m:n 声明本身免费档可存在
（声明非付费）而物化付费——与对象浏览先例同构，无矛盾。

## D5 血缘与重放

- 血缘 kind="link"，spec 增 `junction_dataset/junction_left/junction_right` 三字段；
  n:1/1:1 spec 无 junction 键，重放逐字等价（向后兼容读）。
- `derive_refresh` 按 spec 重连三端最新数据（桥行为最新）——重物化语义一致。

## D6 失存与漂移路径

- 关系/任一端数据集/中间集失存→404 如实（既有语义）；桥列或端点列快照漂移→
  执行前校验拒绝、子集不登记、零半写。
- 旧引擎（link 无 junction）：可读错误（参数不支持），不伪造成功——既有
  「旧引擎如实报错」场景扩到 junction 参数面。
- 工具口径注：本 openspec 版本 MODIFIED 块不允许静默丢场景（archive 拒绝），
  既有场景「m:n 物化不支持如实」**保留原名、改赋新语义**——「不支持」的主体从
  「v0 物化端点」收缩为「旧引擎不支持中间集时如实报错」，与放开后的真话一致。
