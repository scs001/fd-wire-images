## Context

看板渲染链是「产物 spec → DashboardRenderer → 面板分支」：面板按 `type` 分发，
数据一律取面板内嵌 `snapshot`（columns+rows），`query` 只是刷新契约、不参与
渲染。新面板类型因此可以完全落在前端契约层：解析、渲染、编辑器三处，后端零
改动（后端对 dashboard spec 只走通用结构层，宽容校验在前端）。

## Goals / Non-Goals

**Goals**
- 文本内容在柏讯里有可读的呈现形态：图文卡片流。
- 与现有看板完全同权：版本链、分享、橱窗、市场、刷新、导出全部复用。
- 图文安全底线与 doc 产物的渲染纪律一致（纯文本、http(s) 图片、外链加固）。

**Non-Goals**
- 不做 RSS/Atom/JSON Feed 出口（需要新的匿名读边界，另立变更）。
- 不做图片上传/托管/代理（图片以 URL 引用，平台不落二进制）。
- 不做客户端排序、分页或无限滚动（顺序由快照决定，刷新决定新鲜度）。

## Decisions

### D1：新增面板类型，而非新增产物 kind

产物 kind 决定版本链、可见性档位、市场收录与分享令牌机器。新增 kind 意味着
这些面各复制一份判定；而看板已经具备全部所需机制（橱窗只收 `dashboard`、
分享页复用同一渲染器）。把图文流做成看板里的一种面板，客户可以「一块看板上
面放 kpi、下面放信息流」，这是内容型看板最自然的形态。

**备选**：新增 `feed` 产物 kind。否决理由——四套机制要重走一遍，且失去与数字
面板混排的能力。

### D2：角色映射用 `encoding` 列名，不用固定列序

沿用 v2 的 `encoding` 纪律（显式声明列 → 角色），而不是「第 1 列标题、第 2 列
摘要」的位置约定。位置约定在列漂移时会静默错位；列名映射在不命中时能降级。

- `title` 必填；`summary`/`image`/`time`/`source`/`link` 可选。
- 校验宽容：`title` 缺失或列名不在快照列内 → 该面板判坏并标注（与 v1/v2 的
  「坏面板隔离、不整板失败」一致）；可选角色列名不命中 → 只丢该角色，面板照常
  渲染。

### D3：渲染按快照行序，不重排

刷新契约已经能把「按时间倒序取前 N 行」写进 `query`（`sort` + `limit`），渲染层
再排一次会与快照口径不一致（用户在数据表视图看到的顺序应当与卡片流一致）。
因此 list 面板**原样按行序渲染**；时间只用于展示格式化，不参与排序。

### D4：图片与链接只认 `http(s)`，失败即隐藏

- 图片源白名单 `http(s)`；`javascript:`/`data:`/相对路径一律不作为可加载源。
- `loading="lazy"`、`referrerPolicy="no-referrer"`（规避外链站的热链拦截）。
- 加载失败（onError）把图片块整体隐藏，不留破图占位；快照里为空字符串同样
  不渲染图片块。
- 外链 `target="_blank"` + `rel="noopener noreferrer"`。

### D5：文本一律按纯文本渲染

标题/摘要走 React 文本节点，不做 Markdown 解析、不产生 `innerHTML` 注入点。
需要富文本的场景继续用 doc 产物，不在信息流里开这个口子。

### D6：导出与摘要口径照旧

- 整板 CSV 导出：list 面板按快照行原样导出一个 section（与 table 同口径），
  不做图片列特殊处理。
- 市场/橱窗摘要：仍只取 `{id, type, title}`，不因新类型增加字段。
- 公开面红线不变：橱窗仍只服务平台自营 `dashboard`，客户内容不进匿名面。

### D7：AI 生成侧只在数据形态合适时才用 list

生成指令要求：数据含文本列（标题/摘要）且用户表达「信息流/资讯/动态」意图时
才产出 `list`；必须显式声明 `title` 角色；不得把长文塞进 table 假扮信息流。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| 长文本撑破卡片 | 标题两行截断、摘要三行截断（CSS line-clamp），原文经 `link` 外跳 |
| 外部图床防盗链导致图片不显示 | `referrerPolicy="no-referrer"`；失败即隐藏，不破坏布局 |
| 行数过多拖慢渲染 | 面板只渲染快照前 N 行（`config.limit`，缺省 20，上限与查询契约一致） |
| 客户误把敏感图文上市场 | 沿用既有可见性档位与敏感度双点闸，不新增例外 |
| 图文内容被当作「平台推荐」 | 卡片只呈现数据与来源标注，不加入平台侧排序或加权 |

## Migration Plan

- 契约向下兼容：无 `list` 面板的存量 spec 解析与渲染零变化（新类型只是类型谱
  里多一项）。
- 无需数据迁移：list 面板的数据就是普通快照。
- 回归面：分享页、橱窗页、市场摘要、整板导出四处共用渲染/读取链，逐处断言
  存量面板输出不变。
