# Proposal: wire-crawl-source-blocklist — 禁爬源清单（淘宝/拼多多等电商平台硬拒）

## Why

用户明确定规（2026-10-12）：**不允许爬淘宝和拼多多的数据**。这类电商平台
数据涉及平台协议与法务面，属于代爬服务的禁区。当前需求单入口只做了形态
校验（http(s)/无账密/公开数据声明），**没有平台级禁爬清单**——客户可以
提交 taobao.com 链接、运营也可能出单。禁令必须落成服务端硬校验（入口与
出单双闸），不能只靠运营人肉把关。

## What Changes

1. **禁爬源清单**（api 常量，单一出处）：域名后缀匹配的禁爬清单，首版含
   淘宝系（taobao.com / tmall.com / alibaba.com / 1688.com / alipay.com）
   与拼多多系（pinduoduo.com / yangkeduo.com / pddpic.com / duoduoyoucai.com）。
   匹配规则=host 等于域名或以 `.域名` 结尾（防 `taobao.com.evil.com` 类绕过；
   大小写不敏感；含端口/子域均命中）。
2. **提交口硬拒**：需求单表单 `source_urls` 逐条过禁爬校验，命中即 422
   带域名与理由（「该平台数据不在代爬服务范围（平台协议限制）」）——与既有
   合规门（账密/非 http）同点、同形态。
3. **出单闸复检**：工单导出（`export_workorder_service`）对存量单的
   `source_urls` 复检禁爬清单，命中即 409 如实拒（存量单绕过入口的情况
   兜底）——绝不产出含禁爬源的工单。
4. **清单可维护**：禁爬清单以模块级常量+注释出处维护，新增平台=改常量+
   测试，不需要迁移。

### 边界（显式不做）

- 不做通配全电商（京东/亚马逊等未定规，不做扩大化解释——清单显式列名）；
- 不做存量需求单回填清理（存量无禁爬源，实测全库已核实）；
- 不做 client 侧提前校验（前端体验优化挂后续；服务端是唯一裁决面）。

## Impact

api：schemas.py 禁爬常量+校验、orchestration.py 出单复检+测试；web 零改动
（服务端错误文案照常回显）；生产 api 滚版；引擎/cell 零改动。
