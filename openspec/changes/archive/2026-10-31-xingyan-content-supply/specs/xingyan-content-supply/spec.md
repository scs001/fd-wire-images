# xingyan-content-supply

## Purpose

定义星研内容在柏讯供给面的行为契约：从官网三区机读 feed 幂等摄取快照并保留来源指纹，使条目与 claim 成为客户域目录的一等可发现对象，支持 claim 级全局 ID 解析与显式声明的 MCP 工具面，并以只读对账闸守住三处零漂移。

## ADDED Requirements

### Requirement: 快照摄取幂等且失败不冒充空集

供给面 MUST 从官网三个 feed 端点定时并支持按需摄取条目全集与 claim 骨架。同一上游版本重复摄取 MUST 零差异；每次成功摄取 MUST 记录来源指纹（上游版本清单）与摄取时间。上游不可达或响应版本断言不匹配时，供给面 MUST 保留上一成功版本并对外暴露陈旧标记，MUST NOT 返回空集或半版本。

#### Scenario: 幂等重跑

- **WHEN** 同一指纹的上游快照被连续摄取两次
- **THEN** 第二次产生零写入差异，目录与 claim 索引与第一次逐字段一致

#### Scenario: 上游故障显式陈旧

- **WHEN** 摄取时 feed 端点不可达
- **THEN** 消费者仍取得上一版本内容，且响应携带陈旧标记与上次成功摄取时间；不存在「检索结果为空」这一表现

#### Scenario: 版本不匹配拒摄

- **WHEN** feed 载荷的 schema 版本与供给面声明的兼容范围不符
- **THEN** 本次摄取被拒绝并留痕，上一版本继续服务，不猜字段、不部分写入

### Requirement: 条目进目录为一等可发现对象

已摄取条目 MUST 成为客户域目录中的一等记录：slug、分区、双语标题与摘要、发布日期、更新时间、claim 计数与正文指针在目录列表与检索面可见可过滤；默认可见档 MUST 为公开档，MUST NOT 需要逐 cell 加白名单即可被已登录客户的 agent 发现。可见性 MUST 沿用既有档位治理机制，不为本内容新建特权通道。

**承载边界（apply 期定）**：内容为**平台级公开件**，不并入租户数据集目录——`assets`/`market` 两表绑定 `datasets.id` 与 `customer_id`，且其四档可见性刻意不含"公开"（公开面不得含客户数据），并入必须伪造数据集行。故以**独立只读内容目录面**呈现：与数据条目挂在同一个 MCP 工具面，摘要字段形状同构（slug / 双语标题摘要 / 日期 / tags / 计数 / 页面地址），分区过滤语义对齐；见 design D-S1。

#### Scenario: 目录发现

- **WHEN** 客户 agent 经工具面列举目录并过滤研究分区
- **THEN** 返回星研研究条目，其摘要字段与数据条目摘要同构，携带 slug、claim 计数与页面地址

#### Scenario: 匿名档不泄露

- **WHEN** 未登录消费者访问供给面
- **THEN** 其可见性与既有档位闸一致，不因新内容面而绕闸（内容为公开件、快照内物理上无客户数据；客户数据面仍由既有闸判定）

### Requirement: claim 级全局 ID 可解析

全局 ID `slug/claim-id` MUST 在供给面解析为一个确定响应：claim 骨架（类型、证据引用集）、其锚定小节的内容、来源条目列表；同一 ID 经中、英任一语言变体解析 MUST 指向同一 claim。已被上游撤销的 claim MUST 返回显式「已撤销」态并保留登记，MUST NOT 表现为未找到。

#### Scenario: claim 解析到证据

- **WHEN** 客户 agent 以全局 ID 取回一条数字型 claim
- **THEN** 响应含该 claim 的锚小节正文、类型与逐条可解析的证据来源

#### Scenario: 双语同指向

- **WHEN** 同一全局 ID 分别以 zh 与 en 变体请求
- **THEN** 两侧 claim 骨架逐字段一致，正文小节按各自语言返回

#### Scenario: 撤销态显式

- **WHEN** 请求一个上游已标撤销的 claim ID
- **THEN** 返回撤销态与该 ID 的原登记信息，而非空结果

### Requirement: 工具面显式窄声明

供给面 MUST 以显式声明的窄工具面暴露（目录列举、条目检索、claim 取回三类），声明 MUST 逐工具枚举且 MUST NOT 依赖未声明即全量的默认；工具响应 MUST 携带快照指纹与陈旧标记。安装/订阅后的客户会话中，该工具面 MUST 可经在线 tools 列表探到并可用。

#### Scenario: 未声明面不扩张

- **WHEN** 审计该 server 的工具可见面
- **THEN** 可见工具集与在册声明逐名一致，无因上游演化而静默加入的端点

#### Scenario: 响应可归因

- **WHEN** 消费者经工具取回任一载荷
- **THEN** 载荷携带来源指纹，可与目录对账报告互相指认

### Requirement: 三处对账只读零漂移

供给面 MUST 提供只读对账：逐区比对上游 feed 快照、目录条目记录、claim 索引三处的条目数与 claim 集合，输出差异清单（条目、字段、三处取值）；零差异方可宣告收口。对账 MUST NOT 写入或修复任何一处。

#### Scenario: 漂移指名

- **WHEN** 目录中某条目 claim 数与上游 feed 不一致
- **THEN** 对账报告指名该 slug、差异字段与三处各自的值

#### Scenario: 收口留痕

- **WHEN** 对账全绿
- **THEN** 报告含比对时点的快照指纹，作为验收证据归档
