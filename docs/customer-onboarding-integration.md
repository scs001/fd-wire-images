# 客户接入说明：企业隔离与凭据交付方式（wire 对外 / 对接方 + 其 agents）

面向**对接方平台运维与其 agent 集成方**，说明柏讯（wire）如何给一家企业开户、
凭据长什么样、agent 用什么地址与方式接入、能碰到哪些工具、额度耗尽时发生什么。

本文只讲**对外的契约与用法**。平台内部实现与演练记录见
`openspec/changes/add-customer-onboarding-automation/`；平台侧凭据发放与轮换的
操作细节（含服务身份命名、双凭据计量归属）见 `docs/service-credentials.md`；
领域词汇（cell / wire 入口 / 长命 key / 套餐额度 …）见 `CONTEXT.md`。

## 1. 一句话结论

一家企业开通 = 一个**隔离容器（cell）** + 一把**长命 key**；agent 持这把 key 经
**wire 入口**访问两个端点：本企业的 cell（专属数据与工具）与共享业务面。
**企业之间互不可见、互不可调**：A 的 key 既调不通 B 的 cell，也列不到 B 的 cell。

## 2. 开户与交付（对接方需要做什么）

| 环节 | 谁做 | 交付物 |
|---|---|---|
| 提供企业标识 `<customer_id>`（字母数字开头，仅 `[A-Za-z0-9._-]`，≤64） | 对接方 | 一个字符串，后续一切命名都从它派生 |
| 建户、充值、开户（建容器+授权+铸 key） | wire 平台 | 一把明文 key，**仅交付一次** |
| 把 key 配进 agent 运行环境（推荐 Secret/环境变量，0600） | 对接方 | 完成接入 |

平台侧开户是幂等的：重跑不会重复建容器、不会换掉已有授权；同一家企业可以安全重入。

## 3. 凭据形态与使用方式

- 形态：`wgk-` 前缀的长字符串（**长命 key**）。不自动过期；吊销**即时生效**（下一次调用即拒）。
- 用法：作为标准 Bearer 凭据放在请求头——`Authorization: Bearer wgk-...`。
  只认请求头，**不支持 URL 参数传 key**（会被拒）。
- 明文只在交付时出现一次，平台侧只存哈希；**请立即存入受限位置，不要进代码库、
  日志与聊天记录**。怀疑泄露即通知平台吊销，重铸一把即可（旧 key 随即失效）。

## 4. agent 怎么接：两个端点

wire 入口基址：`https://mcp.finddatatech.cloud`

| 端点 | 路径 | 用途 |
|---|---|---|
| **本企业 cell** | `/fd-wire-cell-<customer_id>/mcp` | 该企业专属：客户数据集、私有指标与交付物、企业内分析动作 |
| **共享业务面** | `/fd-find-data-business-mcp/mcp` | 平台共享数据能力（各企业共用一套，权限一致） |

- 传输：**标准 MCP streamable-http**（完整 `initialize` 握手 → `notifications/initialized`
  → `tools/list` / `tools/call`），会话按 `Mcp-Session-Id` 复用。
- 目录可见性：该企业的 key 去列目录，只会看到**共享业务面 + 自己那一个 cell**。
- 跨企业：请求别家的 cell 路径 → **403**；列目录也看不到它。

### 4.1 最小可跑序列（可直接抄）

```bash
KEY='wgk-…'                       # 平台交付的明文，运行时从 Secret 取
BASE=https://mcp.finddatatech.cloud
CELL=/fd-wire-cell-<customer_id>/mcp

# 1) 握手（记下响应头里的 Mcp-Session-Id）
curl -sS -D - -o /dev/null -X POST "$BASE$CELL" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"your-agent","version":"1.0"}}}'
```

拿到 `Mcp-Session-Id` 后：先发 `{"jsonrpc":"2.0","method":"notifications/initialized"}`
（带同一 session 头），再发 `tools/list` 取工具清单，然后 `tools/call` 调具体工具。

> 直连容器地址（不经 wire 入口）只用于开发调试，**禁止用于客户数据读取**：
> 计量与权限都在入口这一层。

## 5. 计量与额度（对接方需要知道的行为）

- **计费归属跟着凭据走**：用客户 key 的调用计入该企业账单（客户轨）；平台侧探索性调用
  走平台服务凭据，不进客户账单。两边互不混淆。
- **额度耗尽即硬停**：该企业账户余额不足时，入口直接返回
  `402 INSUFFICIENT_BALANCE`，请求不会打到上游——agent 侧应把它当作
  「需要充值」的明确信号，而不是重试。
- 余额恢复后调用**自动恢复**（判定结果有约 30 秒缓存窗口，最坏情况等一分钟）。
- 若某企业的调用被返回 `402 CALLER_NOT_MAPPED`，那是**开户映射缺失**（未完成计费开户），
  请联系平台补开户——不是余额问题。
- 若返回 `402 BILLING_ACCOUNT_MISSING`，那是**计费账户不存在**（映射在、账户没建成或
  id 填错）——同样联系平台核对开户，**充值无效**。
- **已知口径提示（拆分前的临时说明）**：`402 INSUFFICIENT_BALANCE` 目前
  也用于「计费侧查不到该企业账户」这种开户缺口情形（平台侧日志表现为读
  用户 404）。因此**充值后仍持续 402 时不要反复重试**，直接联系平台核对
  开户配置。平台正在把两种情形拆成独立错误码（见
  `docs/registry-requirements.md` R6），拆分完成后本条即失效。

## 6. 吊销、轮换、退租

- **轮换**：向平台申请新 key → 拿到后更新 agent 运行环境的 Secret → 通知平台吊销旧 key。
  因凭据在容器创建时注入，轮换可能伴随一次**容器重建**，平台会提前告知窗口。
- **吊销**：即时生效，不可逆。误吊重铸即可。
- **退租**：平台侧一条命令完成「吊销凭据 → 收回授权 → 摘除入口条目 → 数据卷进入保留期」，
  保留期内可撤销恢复（恢复后需重新授权），到期清除。

## 7. 对 agent 实现的建议

- 凭据只从环境变量/Secret 读取，**不写进提示词、不打印、不随日志外发**。
- 把 401 当「凭据无效或已吊销」→ 停止并告警人工介入；把 402 当「额度问题」→ 停止并提示充值；
  403 说明**目标不在授权范围**（写错了别家路径或越权），不要重试。
- **注意**：访问一个不存在或未授权给本企业的 cell 路径时，当前可能返回
  **405**（入口无该路径，落到兜底路由）而非 403——请按与 403 相同的
  「越权/路径写错」处理，**不要重试**（平台正在统一为 403，见
  `docs/registry-requirements.md` R1a）。
- 会话要复用：每次调用都重新 `initialize` 会产生多余会话与开销。
- 不要把跨企业的路径/标识硬编码；cell 路径总是由 `<customer_id>` 派生。

## 8. 变更与兼容性

本次（2026-10-08/09）的处理方式要点，供对接方评估影响：

- 企业隔离与凭据发放**全部自动化**：开户不再依赖任何人工 ceremony，
  授权随开通即时生效、随退租即时回收。
- 隔离策略是**按企业精确授权**，不是靠命名约定猜：新增/注销企业不需要改动其他企业的配置。
- 计量归集走了**平台主动拉取审计流**的口径：一般数秒内入账，最坏一个轮询周期（5 分钟）。
- 对外契约（端点形状、凭据形态、MCP 传输、错误码语义）**保持不变**；本次变更不要求
  对接方改代码。后续若调整端点或错误码，会另行通知并给迁移期。
