## 1. 北极星

**柏讯的终局 = 类 Palantir 的企业数据中台**：把企业各处的数据汇聚进来，在其上做
AI 分析与管理；同时长出 Palantir 没有的两个器官——**自有数据供给引擎**（客户缺
什么数据，平台采给你）和**宏观指标护城河**（57,553 指标的统一注册目录，接进来第
一天就有别人没有的数据可连）。**双侧形态**：企业侧（B2B 中台+应用平台，方向
A/B/C）与个人侧（C 端信息工作台，方向 D）——同一个供给引擎、同一套产物与分享
地基，两种客户形态。

一句话定位：**宏观指标加持的企业数据中台——客户的业务数据进来，第一天就能连上
五万余个宏观/行业指标。**

## 2. 全景图

```
第⓪层 供给引擎（爬虫平台 panel + 万星生成/自愈双链）      ← 柏讯独有

   ↓

   ↓

   ↓

```

## 4. 三大战略方向

### 方向 A：数据中台深化（存储与语义的地基）

**存储路线已拍板（2026-10-11）：柏讯单独产品条线 = 专用 PostgreSQL。**

- 两层迁移，风险差一个量级：
  - **api 元数据层**（低风险纯收益）：多个 SQLite 库文件（api/datasets/demands/ai）
    → 一个 `wire_platform` 库；Alembic 已在管；解决并发写互顶、审计事务、/tmp 脆弱债。
  - **cell 数据根层**（真工程）：每客户 SQLite 卷 → per-cell `cell_<key>` database
    （一卷一库，隔离语义原样保留且更硬）；经 DAAS_PROFILE 存储画像发 postgres URL，
    謙面同源不分叉；cell-manager 增加"建库+发凭据"步骤（凭据入 OpenBAO）。
    **v1 已上产（2026-10-12，wire-cell-postgres-storage）**：引擎可选 PG 数据根
    （双方言矩阵 sqlite/PG 双绿，sqlite 默认字节不变）+ 一 cell 一库属主凭据纪律
    （库级 ACL，平台角色无 CONNECT）+ drillcust001 试点搬迁与回退演练实弹通过。
    **v2 已上产（同日，wire-cell-pg-provisioning）**：cell-manager 自动「建库+
    发凭据」——CELL_STORAGE=postgres 七步全自动（隔离四查自动验证、凭据入
    OpenBAO 受限 token、purge 删库语义、backup.sh 动态发现 wire_cell_%），
    试点 pgauto001 零手工 SQL 全链实证；剩余=存量 sqlite cell 逐户编排、
    `pg_database_size` 配额重估、OpenBAO auto-unseal。
  - 三条 spec 红线：①凭据纪律重述「永不直读」——cell 库属主凭据只归该 cell 引擎，
    平台管理角色策略禁读业务数据（**v2 已落为库级 ACL+自动隔离四查**）；②50 万行
    上限从"保护 SQLite"转为商业配额杠杆（`pg_database_size` 计量）并重估数字
    （**机制已上产 2026-10-12 wire-cell-storage-quota：可选配额整批拒绝+用量观测，
    与行数闸叠加；数字重估=产品决策待办**）；③存量 cell 低峰逐户搬、卷保底可回退
    （**回退语义已试点实证**；编排待更多存量 cell）。
- 语义层升级：轻量实体建模（实体+主键互链+关系声明），join 从"表连接"升为
  "业务语义连接"——中台化绕不开，但不必做全量本体。
  **v0 已上产（2026-10-12，wire-entity-layer）**：实体/关系声明+图谱+图谱注入
  AI 构建上下文+控制台实体页；数据集间物化 join（引擎 link 工具）
  **已上产（2026-10-13，wire-transform-pipelines）**：`customer_dataset_link`
  引擎实现+注册（LEFT JOIN 物化、lineage kind=link、重放、能力旗），实体物化
  端点转正，并为管线 link 步骤提供原语。
- 顺手解锁：增量水位同步、大表、变换管线（④层管线化）。

### 方向 B：应用平台层（把分析变成客户的应用）

客户能**自定义看板**、用**可修改的表单页**记录和处理数据、把成果做成**成熟的 web
直接分享给别人用**。这是 Palantir Workshop 的领地；国内对标简道云/明道云一族，但
柏讯起步就带数据。

- **后端地基大半现成**：表单写的语义 = 既有 overlay 修正层（带审计、重同步存活、
  可回滚）；`rows:batchWrite` + `columns` 写路径在；`wdk-` 数据面 key 可限定数据集
  允许清单 = 查看者数据面权限；`bff-reference` 已开源 = 浏览器经 BFF 访问的范式。
- **行动环注解**：表单写的是 wire 侧副本（overlay），与「永不写回客户源」零冲突；
  该不变量继续约束的是连接器同步通道。真正留白的只剩"写回客户业务系统"（ERP 回写），
  立场未决，默认不做。
- 缺件按序：**产物转正**（草稿→服务端持久化+版本化，溯源账本做底座）→ 看板渲染器
  +手工编辑器（AI 生成与手工编辑共用同一种 spec，双轨读写）→ 表单构建器/运行时 →
  签名链接分享（免登录+允许清单+限流；既有红线：公开目录/渲染层不得含客户数据，
  分享页不得被目录或搜索引擎命中）→ 团队空间（二期）。
- **进度（2026-10-12）**：前四项均已上产（wire-artifacts-persistence / dashboard 全线 /
  wire-form-builder 表单构建器+运行时+公开提交 / dashboard-share+form 分享）；
  **团队空间 v0 已上产**（wire-team-spaces：N:1 成员 + wsi- 一次性邀请码 24h +
  owner/editor/viewer 三角角色门禁入统一鉴权依赖 + team_events append-only 审计；
  v0 边界=一人一队、无按席位计费、无邮件邀请）；
  **表单字段联动已上产**（wire-form-field-linkage：字段级条件显隐 visibleWhen
  九算子、隐藏即清值不进载荷、公开提交端点同规求值防篡改 422、双端求值 16 例
  对拍逐字一致）；方向 B 主线+v1+ 深化全部落地（**表单联动 v1+ 已上产 2026-10-12，
  wire-form-linkage-v2：visibleWhenGroup 多条件组合（all/any）+
  optionsFrom 联动改选项（级联 select/空选项按隐藏/公开提交动态成员
  防篡改）**，生产实弹全绿）；**团队空间二期已上产（2026-10-13，wire-team-spaces-v2）**：多团队（成员行 (customer_id, logto_sub) 唯一 + per-sub 活跃队指针与切换端点 + guesting owner 语义）+ 席位配额（档位 limits_json.seats，free=1/basic=3/standard=10，双闸 409 零超额）+ 角色变更端点；邮件邀请因邮件通道缺位继续挂账（链接复制邀请在役）；团队所有权转移留 v3 团队实体化。
  **数据开放与市场已上产（2026-10-13，wire-dataset-marketplace）**：四档可见性阶梯
  （private 默认 / link / directed / market）+ 开放模式（open 订阅即得 / approval 需批准）
  + 定向授权名单 + 市场浏览检索订阅 + 审批流；读经数据面只读（他人数据永不写入），
  计量记消费方；撤回/退订/拒绝即时失效。红线 3 同步修订（§7：opt-in 例外）。
  **三件必须项结项（Q15，2026-10-14）**——用户原始裁决「规则引擎和公开分享的
  数据集和看板是我们必须做的一个工作」的三件全部交付：①**规则引擎** =
  wire-quality-rules v1+v2（2026-10-13/14，自定义合格线 + 引擎侧 pandera
  内容检查）；②**数据集公开分享** = wire-dataset-marketplace（2026-10-13，
  四档可见性 + 市场 + 订阅/审批）；③**看板/报告公开分享** =
  wire-artifact-marketplace（2026-10-14，产物四档可见性 + 市场「看板/报告」
  页签 + 只读看/可复制双语义——公开看板含发布时刻数据快照、文案如实披露；
  复制剥离快照仅传分析结构）。

### 方向 C：供给引擎（数据中台的上游）

panel 爬虫平台 = **客户获取信息的桥梁** + **自身项目目标信息的供血系统**。双角色
今天都已在役；缺的是把桥的中间段自动化。

- 现状：桥两端已通——wire 需求单（submitted → in_progress → delivered，另 rejected
  终态必附理由）交付时自动开私有 scope（失败可重试；**wire-demand-visibility 已补
  管理台路径同语义**——此前管理台流转漏钩子，运营主路径交付不开 scope，真缺陷已修）；
  fleet + 万星生成/自愈双链 + 指标注册（verified 双闸）+ conformance 门全部在役。
  **交付私有 scope 已点亮（2026-10-12，wire-scope-delivery-live + 上游
  fd-open-data-mcp scope-rest-api）**：交付即自动建 demand-<code> 私有 scope
  并逐指标 grant（生产实弹 ok）；delivered+pending 单可经内网/管理台「重试开
  scope」补课（支持 indicators 覆盖）；此机制此前因上游无 REST 面+wire 无
  重试端点而恒 pending——最后一环补齐。
  **中间段编排已在役**（工单 YAML→舰队拉取→萬星生成→PR→回流，生产实证）——
  **「触发出单」也已自动化（2026-10-12，wire-demand-auto-export）**：受理
  （submitted→in_progress）后后台补扫 60s 内自动出单入拉取队列（trigger=auto
  标注），被拒如实落 auto_export_failed 留痕由运营面呈现、人工入口可重试——
  「客户提单到 agent 开工」之间零人工点击。运营侧进度面（七阶段时间线+gate+
  交付状态）与客户侧交付就绪面已上产。
- 目标编排：需求单 in_progress 段从人工变 agent 驱动（萬星对话即生成）+ 人工抽审。
  **现已达成**：受理即触发自动出单，编排中间段+触发段全自动，人工只在
  合规审查（受理动作本身）与 PR 人审两个把关点介入。
- **飞轮**：客户需求 → 采到的数据进共享指标目录 → 所有客户可用 → 目录越厚平台
  越值得买。每次代客采数都是对平台资产的永久投资——Bloomberg（数据壁垒）与
  Palantir（平台能力）的合体。
- 前置规矩：①**合规审查门**——代爬有真实法务面（robots/个人数据/版权/付费源），
  需求流程必须有合规清单+人工放行闸，接客放量前定好规则集（**自动触发的前置**；
  **首条规则已落规并上产**：wire-crawl-source-blocklist=禁爬淘宝/拼多多系九域，
  提交口 422+出单闸 409 双闸硬拒，用户定规 2026-10-12）；
  ②商务口径（**用户裁决 2026-10-12：按数据获取报价**——需求单
  独立报价，报价随源数量/难度/频率等获取成本要素评估；代采数据进
  共享目录还是客户私有数据集按报价区分，不影响既有免费/基础/标准自助档）
  （**萬星直连已上产 2026-10-13**：wire-wanxing-direct-dispatch 归档——
  需求单第二条投递通道，A2A 直投 spider-heal 同步回执；drill 实弹全环
  打通=直连工单→agent 生成爬虫→fd-industry-data PR#59 当日可证；幂等键/
  失败留档/不进拉取队列齐备；调用打新域 wanxing.finddatatech.cloud；
  剩余仅充值策略属用户）；③客户侧进度可见性
  （**已上产：七阶段运营面+客户四阶段时间线+交付就绪；「已入库」阶段无信号源挂远期**）；④交付 SLA 预期管理。

### 方向 D：个人信息工作台（C 端）——快速搭建

**目标**：让终端个人用户能处理**数百个信息源**的数据，优化其信息处理能力；用户
**持续优化和迭代**自己的这套体系，能**分享给别人看**，能**直接和 agents 对话**
（2026-10-11 定调，明确要求快速搭建）。

本质 = 把中台能力下放到个人尺度：**个人信息中枢**。五件事对现状的映射：

| 目标 | 现状 | 缺件 |
|---|---|---|
| 数百个信息源 | 供给引擎+指标目录已在（57,553 指标、95+ 行业单元、宏观/法律线） | **源包订阅视图**——个人不订"指标"，订"信息源/主题包"（如某行业包、宏观包），从目录打包 |
| 优化信息处理 | AI 构建对话、看板、MCP 工具；**薄工作台已上产**（wire-personal-workbench：六段聚合一屏看全+空态上手 CTA） | 个人化编排深化（工作台联动编排/快捷动作） |
| 持续优化迭代 | **个人偏好持久化已上产**（wire-personal-preferences：per-sub 语言/落地页/置顶看板跨端同步+置顶指针自愈） | **偏好演进史**（用户调的 prompt/规则/看板选择随时间演进的版本化——溯源账本做底座，远期） |
| 分享给别人看 | 全站零分享机制 | 同方向 B 签名链接（两方向共用一建） |
| 直接和 agents 沟通 | AI 构建 chat 已在；壹座用户经 Backend-Auth 回退**今天就能调 wire 共享业务面** | 个人版对话入口的轻量化包装 |

**关键发现——免费档门控挡的正是个人用户**：自助注册的个人天然是 free 档，而
free 档打开「我的数据」只见升级引导（§3 可见性三断点）。C 端起步必须先解这题
（放行+限额，而非整页隐藏）。

**架构决策（快路径）**：cell-per-person 太重（每用户一容器撑不住 C 端规模，且引擎
单用户不感知多租户）——个人侧一期走**共享业务面 + 个人产物区**：数据读走共享
business-mcp / REST，个人上传与产物落 PG（方向 A 的 per-user 库/形态，正好用上），
不建个人 cell。与壹座的边界：壹座=通用 agent 执行平台（人用），柏讯个人侧=带数据
底座的信息工作台；壹座可作为个人侧的 agent 宿主（MCP 已通），柏讯自己出薄工作台
web。规模验证后再考虑轻量个人 cell。

## 5. 差异化定位（为什么不是复刻）

| 对比 | 他们 | 柏讯 |
|---|---|---|
| Palantir Foundry | 平台强、数据客户自带、重咨询部署 | 自助 B2B；平台+供给引擎一体 |
| Bloomberg/Wind/CEIC | 数据厚、无企业数据平台 | 数据目录 + 客户数据中台一体 |
| 简道云/明道云 | 应用层强、数据从空表开始 | 应用层起步就有数据（自有+指标） |

护城河三件套：**宏观指标目录的即接即用 join**、**自助 B2B**、**可离线验签的溯源
纪律**（修正→WAL→账本→证据包，Foundry 没有的对外形态）。

## 7. 立场与红线（跨方向不变）

1. **永不写回客户源**：连接器同步通道永远只读客户源；表单/编辑写 wire 侧副本
   （overlay），审计可回滚。
2. **平台侧永不直读 cell 数据**：读必经引擎工具；PG 化后以凭据纪律落死
   （见方向 A 红线①）。
3. **公开目录与渲染层不含客户数据**：目录搜索不命中客户数据集（既有 E2E 红线）；
   分享页不得入公开目录或搜索引擎。**例外（2026-10-13，wire-dataset-marketplace）**：
   客户显式选择开放档位（`link`/`directed`/`market`，可随时改回 `private`、留痕可查）
   的数据集按档位对相应对象可见——`directed` 仅授权名单客户、`market` 为登录客户可检索的
   数据市场（保留 noindex、不对匿名访客开放）；**`private`（默认）的数据集永不出现在任何
   目录、市场面或检索结果**；敏感度「敏感」档只允许 `private`。此例外守住红线核心意图——
   客户私有数据不会被动泄露，只有主动选择开放后才会被相应对象发现；访问权仅只读
   （他人数据永不写入），撤回/退订/拒绝下一次请求即失效。
4. **云端零客户源凭据**（ADR-0004）：连接器本地 0600 保管，吊销即时生效。
5. **双凭据计量归属**：AI 探索走平台凭据不计客户账，产物物化走客户凭据按行计量。
6. **数据接入公开宣称纪律**（content-integrity）：能力上线同批配文档，不先宣称。
