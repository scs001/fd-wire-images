# Customer source credentials live only in the connector (cloud holds zero source credentials)

客户源（内网数据库/本地文件）的账密只存连接器本地，平台云端从录入到运行全程不接触、不存储任何客户源凭据。云端下发的是共享白名单与调度（哪些表、多久同步），不是凭据——连接器凭它自己持有的受限数据库账号能够到哪些表，云端白名单只能在这个边界内做选择题。这样选是为了 B2B 安全审查：客户 IT 最关心的问题「平台拿我数据库密码能干什么」从根上不成立；出站外联 + 受限账号 + 云端零凭据构成三层最小权限叙事。

## Considered Options

- **云端托管凭据**（客户在控制台填账密、加密保存并下发给连接器）：配置顺滑、可云端代测连通性，但云端成了蜜罐，一次云侧泄露即波及所有客户源；且「平台存了我的密码」在销售环节是实打实的异议点。否决。
- **云端零凭据**（本决策）：牺牲云端代测的顺滑度（连通性由连接器本地检测、回报结果），换蜜罐面归零与安全叙事。

## Consequences

- 控制台不提供云端代执行的「测试连接」；连通性与同步错误由连接器回报、控制台如实展示。
- 客户源账密的录入、轮换、账号变更全部在客户侧连接器配置完成，云端无感知。
- 将来若加实时查询隧道，本立场不变：隧道两端只传查询与结果，不传凭据。
