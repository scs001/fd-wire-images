# Metering attribution is dual-credential: platform pays for AI exploration, customer pays for materialization

每笔数据调用的计量归属由发起时所用的凭据决定：AI 对话构建过程的探索性调用走平台服务凭据——平台担成本（token 网关侧限轮次/限 token），用量按来源归集、不出现在任何客户账单；产物物化（仪表盘刷新、组合指标计算、报告出数）走客户长命 key——行数计量入客户账单。计费单位是行（`rows_returned`）不是调用次数：一次 AI 对话几十次探索调用，按次计费账单不可预期；按行对齐客户心智「拿到多少数据」。

## Considered Options

- **全部记客户**（AI 构建过程也计费）：探索是试错，客户为废招付费等于惩罚使用 AI——与「AI 对话为主入口」的产品定位直接冲突，吓退构建等于吓退留存。否决。
- **全部记平台**（物化也免费）：定时刷新/报告出数是持续性成本且直接产出业务价值，免费物化=客户可无限白嫖刷新频次，成本侧无闸门。否决。
- **按调用意图标记**（服务端猜这笔调用是探索还是物化）：意图在调用侧不在报文里，猜错的计费争议不可审计。否决。
- **双凭据**（本决策）：归属跟着凭据走，每笔计量记录带凭据轨道标记——可审计、可对账、可分轨呈现。

## Consequences

- 账单与对账报表分轨呈现（客户轨/服务凭据轨）；壹座/萬星生态调用 wire 数据同走服务凭据轨道，按来源归集不结算（paas ADR-0014 边界结算哲学延伸），未来商业化可依归集数据开结算、不承诺。
- 平台担成本侧需防滥用：AI 构建循环的轮次与 token 预算限档在 token 网关侧执行，异常用量后台可见。
- 硬停语义作用于客户轨：额度耗尽后交互查询与定时刷新一律拒绝（预检 402 + 账本硬停一致），恢复途径如实展示。
- 双凭据划界意味着同一 cell 内两套凭据并存：探索凭据的可见范围与吊销语义必须与客户凭据显式区分，不得混用。
