# 业务写并入修正层机制，以通道归属区分语义

业务系统把柏讯当主存储后，应用与 agent 的写入（原始事实的产生）与人工修正（对快照的纠错）共用同一条修正层机制：同一 overlay 存储、同一审计、同一回滚与重放语义；每条编辑记录携带结构化通道归属（console 成员 / 数据面 key / agent）区分语义。否决的单开业务写路径会分裂审计与回滚语义、工程翻倍；纯「修正」词汇会让审计面长期把业务事实误读为纠错。

## Considered Options

- 单开业务写存储路径（否决：审计分裂）
- 词汇统一叫「修正」不加通道（否决：语义错位，订单写入不是修正）

## Consequences

- 无连接器的数据集上，修正层退化为带完整审计日志的可编辑表——这是特性不是妥协。
- 溯源账本（WAL→封存→验签）天然覆盖业务写，通道字段随事件流透传。
